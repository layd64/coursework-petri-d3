# Імітаційна модель системи передачі даних на основі стохастичної мережі Петрі

Програмна частина курсової роботи з освітнього компонента «Комп'ютерне моделювання
дискретно-подійних систем». Завдання D3, формалізм - стохастична мережа Петрі.

Пакети обмінюються між пунктами A і B дуплексним каналом. Якщо буфер пункту заповнений, пакет
передається резервною супутниковою лінією, а якщо й вона зайнята - втрачається. Програма оцінює
частоту викликів супутникової лінії, її завантаження та обсяг буфера, потрібний для роботи без втрат.

Імітацію виконує алгоритм бібліотеки PetriObjLib. Його спрощено під умову задачі в каталозі
`PetriObjLib-modified`, кожну зміну позначено коментарем `[D3]`. Оригінал лежить у `PetriObjLib-master`.

## Структура

```
CourseWorkPetri/
├── pom.xml                  Maven-проєкт: два варіанти бібліотеки + модель
├── run.sh                   збірка і запуск
├── PetriObjLib-master/      бібліотека PetriObjLib без змін
├── PetriObjLib-modified/    бібліотека зі спрощеннями під задачу
├── d3-model/src/main/java/ua/kpi/d3/
│   ├── Main.java            точка входу, команди
│   ├── model/               параметри моделі та побудова мережі Петрі
│   ├── sim/                 запуск прогону, збір статистики, протокол, перевірка інваріантів
│   └── experiment/          експерименти, паралельні прогони, статистичні методи
├── scripts/plots.py         графіки за результатами
├── diagrams/                схеми BPMN і мереж Петрі
└── results/                 результати останнього повного запуску
```

## Збірка і запуск

Потрібні JDK 17+ і Maven 3, для графіків - Python 3 з matplotlib.

```bash
./run.sh all
```

`run.sh` сам збирає проєкт, якщо код змінився. Без скрипта:

```bash
mvn package
java -jar d3-model/target/d3-model-1.0.jar all
```

Повний `all` триває близько 7–8 хв. Скорочена версія для перевірки триває близько 45 с і пише
в окремий каталог `results-quick/`:

```bash
./run.sh all --quick
```

Графіки будуються з CSV-файлів результатів у `<каталог>/plots/`:

```bash
python3 scripts/plots.py results
```

## Команди

| Команда | Що робить |
|---|---|
| `all` | усі експерименти послідовно (за замовчуванням) |
| `run` | один прогін з довільними параметрами |
| `protocol` | протоколи подій |
| `verify` | верифікація: варіювання вхідних змінних, інваріанти, затримки, конфлікт |
| `transient` | тривалість перехідного періоду |
| `baseline` | кількість прогонів і оцінки вихідних характеристик |
| `normality` | закон розподілу оцінок частоти викликів і завантаження |
| `intervals` | закон розподілу інтервалу між викликами супутника |
| `steady` | вплив обсягу буфера, регресійний і дисперсійний аналіз |
| `lossfree` | обсяг буфера для роботи без втрат |
| `factorial` | повний факторний експеримент 2^3 |
| `proposals` | перевірка пропозицій щодо поліпшення системи |
| `duplex` | пропозиція з дуплексною супутниковою лінією |
| `speed` | порівняння швидкодії оригінальної та модифікованої бібліотеки |

## Опції

| Опція | Значення |
|---|---|
| `--quick` | скорочені експерименти, результати в `results-quick/` |
| `--out <каталог>` | каталог для результатів |
| `--threads <k>` | кількість потоків для паралельних прогонів |
| `--lib original` або `--lib modified` | варіант бібліотеки, за замовчуванням модифікована |
| `--warmup <мс>`, `--T <мс>` | перехідний період і час спостереження |

Опції команди `run`: `--N <n>` - обсяг буфера, `--T <мс>`, `--warmup <мс>`,
`--arrival <m> <d>`, `--channel <t>`, `--sat <m> <d>` - параметри затримок, `--protocol` - друк
протоколу подій.

Приклади:

```bash
./run.sh run --N 5 --T 600000
./run.sh run --T 150 --protocol
./run.sh verify --lib original
```

## Результати

Кожна команда пише консольне виведення у `<команда>_log.txt`, протоколи подій - у
`protocol_*.txt`, а дані окремих експериментів - у CSV-файли з роздільником `;`, наприклад
`baseline_summary.csv`, `buffer_steady.csv`, `factorial_f.csv`. Графіки зберігаються в `plots/`.
